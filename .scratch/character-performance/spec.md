## 已同意深化的骨架

```text
SceneDesign.elements[]
  既有造型与视觉职责：人物身份、轮廓、服装、敌对气质的可见线索
  performance
    动作
      动作阶段
        身体姿态 / 头部朝向 / 注视目标 / 表情 / 手脚关系
    观察方向下的表现要求

资产制作
  引用人物、动作阶段与选定观察方向的生图任务
  任务对应的源图与实际裁剪记录
```

用户已同意本骨架与第二轮的动作范围、方向覆盖。人物外观不在每个动作重复定义；动作语义先决定要演什么，制作任务再决定画哪些组合。身体与头部朝向需有明确参照，注视目标与观察方向分别表达；“正面图”不能替代“对视”。完整字段与走读见 [人物表演与制作字段 v0.1](fields-v0.1.md)，当前仍是设计文档，未接入引擎。

后续要讨论：动作阶段与关键帧的关系、必要观察方向、跨帧身份一致、裁剪留白与统一尺度、脚底基准，以及制作结果怎样对应运行时动作。不预先锁死现有六帧或为所有动作生成全部方向的组合。

## 第二轮字段草案

以下用于讨论，并未替换旧字段或接入引擎。沿用人物现有 `form / surface_uses / visual_role` 定义外观及身份，避免在每个动作中复制一套角色。

```text
performance
  actions[]
    id / name / intent
    target                         此动作面向的对象，例如对手；无对象可为空
    loop                           是否循环表演
    phases[]                       按动作发生顺序排列
      id / intent
      pose
        torso                      躯干朝向与倾斜，相对于角色前方或动作对象
        head                       头部相对躯干的转向与俯仰
        gaze: {target, manner}     看向谁、怎样看；与头部转向分别填写
        expression                 眉眼、嘴部等实际可见表情
        arms_hands                 左右臂与手的形状、伸向和遮挡关系
        legs_feet                  腿脚支撑、步态与接触位置
        weight                     重心怎样偏移
      transition                   怎样进入下一阶段，循环末段怎样接回首段
    view_readability               不同观察方向下必须保住的轮廓与关系
```

阶段表达有意义的动作变化，不直接等于一张 PNG；需要几张关键帧由制作计划展开。原 `preparation / key_pose / recovery` 可分别进入阶段；受击与倒地也是动作，避免另外维护一套不兼容的姿态结构。此迁移尚未执行。

例如重型恶徒的直拳：预备阶段肩略收、拳贴颊、压眉直视对手；发力阶段后脚蹬地、肩腰送出、攻击拳伸向对手、另一拳护脸；收势阶段收臂并重新形成前压戒备。这些是动作内容，生成提示还需加入选定的脸、衣着与具体观察方向。

同一拳从侧面观察时，眼睛仍看向对手，不能为迎合侧面观察镜头而改成看旁观者。正面交战生图时，对手位置与玩家镜头相合，才明确要求镜头对视。

### 制作交接建议

- 生图任务引用角色、动作、阶段与观察方向；同一角色同一视角的一段动作安排为一个短图组，先用选定外观固定脸、服装和体型。
- 裁剪记录对应具体源图及画格。保留统一的人物尺度和支撑基准，动作伸展由留白容纳，不逐帧自动撑满画布；跳起或倒地时表达有意的接触变化。
- 不把裁剪当成修复画错的眼神、身份或肢体。实际透明处理、图集布局和运行时映射在制作阶段明确，不继续冒称现有 RGB 色键图为透明素材。

### 第二轮已确认

用户回复“都很好”，确认如下：

1. 动作粒度。首轮具备待机威胁、戒备、行走、直拳、受击与倒地；行走有交替支撑的循环，直拳有预备、发力、收势，受击与倒地有连续姿态变化。先让身体真正换姿势；格挡、勾拳及更多招式之后按需增加。
2. 方向覆盖。首轮完成正面交战动作，左右前斜视角先覆盖待机、戒备与行走；schema 可逐项增加其他动作方向。这个范围不代表已有完整绕背表现；侧后及背面动作需另补，不能用正面图冒充。

首个字段走读建议采用宽肩重型恶徒，再用纤细角色的回头观察或受击检视，避免把所有动作写成握拳、对视和同一种重心。
