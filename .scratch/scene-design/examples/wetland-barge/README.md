# 第二个实例：雨夜驳船穿越湿地

2026-09-10。用于检视 Schema 的通用性。该目录包含填写内容，通用字段定义在 [v0.2](../../fields-v0.2.md)，没有新增名为 BargeScene 的专用 Schema。

用户提供了码头登船、经过湿地、草岸攻击、敌船接近、穿越拱桥、上岸衔接下一场景的构想。本例据此提出具体美术和体验安排；桥的数量、轮廓、路线弯曲、人物造型等仍是提案。没有修改当前 Godot 小样，没有生成本轮计划的图片。

## 三组契约，第二个主方案

| 契约 | 本例内容 |
| --- | --- |
| ProjectArtDirection | 复用 [已有项目美术约定](../project-art-direction.json)，`noir_comic@draft-01` |
| SceneDesign | [湿地航行主方案](scene-design.json)，`wetland_crossing@draft-01` |
| VisualProductionPlan | [移动视角探索计划](visual-production-plan.json)，`wetland_moving_views@draft-01` |

`barge`、`bridge_a`、`reed_raiders` 是这份实例的物件 ID，不是 Schema 中强制出现的字段。换成缆车、列车、徒步队伍时仍使用 elements、motion、routes、experience 和 views，再填写相应对象与关系。

```text
同一份 ProjectArtDirection
├─ SceneDesign：雨夜唱片店
│  └─ VisualProductionPlan：店面、橱窗、人物与进店分镜
└─ SceneDesign：湿地航行
   └─ VisualProductionPlan：岸上/船上观察、船体研究与航行分镜
```

## 一份主方案里有什么

场景包含六个区域：出发码头、芦苇水道、低桥下、开阔水面、高桥及弯道、终点石阶。五处连接表达它们如何相接，一条七段路线表达如何依次经过。

```text
南：码头登船
    ↓
进入芦苇水道 → 左岸人物显露攻击
    ↓
第一座低宽三孔桥 → 岸上来向被遮挡
    ↓
开阔水面，偏向东北 → 右后方敌船接近
    ↓
第二座较高单孔桥 → 桥墩与弯道截断后方视线
    ↖
西北支汊靠岸 → 固定石阶 → 下一场景尚未设计
```

整体美术并不复用唱片店的物件内容。本例以青灰水面、黑绿草岸、移动暖灯、冷白敌船灯和两种石拱轮廓建立自己的主形象；线条、块面明暗、细节尺度和二维人物融合规则仍然共用。

## 移动关系怎样表达

| 对象 | 描述所在字段 | 具体关系 |
| --- | --- | --- |
| 两座桥、终点灯 | elements 的固定默认 | 保持世界位置 |
| 驳船 | motion.mode = route | 沿 main_waterway 前行 |
| 追击船 | motion.mode = local | 从侧后方接近，在第二桥减速退出视线 |
| 驾驶者 | motion.mode = attached | 始终站在追击船尾部，随船移动 |
| 船首灯、追击灯 | lighting.anchor_element_id | 随各自船体移动，不留在初始码头 |
| 甲板绳圈和货箱 | dressing.anchor_element_id | 相对于驳船摆放 |
| 玩家取景 | camera.anchor_element_id | 船上时依附驳船，登船前和上岸后用世界位置 |

初始区域不代表物件永远被锁在那里；体验时刻的 situation 给出画面相关对象当时的状态。实体依附关系继续生效，例如驾驶者未在每一时刻重复列出时，仍随追击船移动。

## 体验设计先于分镜

七个 experience 时刻明确设计：登船、离岸、草岸威胁、低桥、追击、高桥、上岸。progression 引用这七个 ID，并用自然语言说明推进条件。

每个遭遇的造型与事件分开：

- elements 设计草岸人物和追击船的轮廓、材质、二维/三维分工及受光。
- experience 中的 encounters 说明何时显露、从哪个方向攻击、玩家如何看清、怎样被空间遮挡或退出。
- VisualProductionPlan 选择这个时刻的观察位置，不另编攻击顺序。

不会要求所有静态场景都填写敌人；删除这个案例的两个 encounter 并调整相关动作描述，仍能保留完整的湿地游览设计。此处没有战斗数值、AI 状态机或可运行的事件代码。

## 一个取景的输入展开

`v_pursuit` 的含义是：

```text
场景主方案：wetland_crossing@draft-01
体验时刻：m_pursuit
路线进度：main_waterway / r_open / 两桥之间
玩家参照：驳船船首左侧
镜头动作：从原站位转看右后方
当时状态：敌船位于驳船右后方，有明确水面间隔
人物关系：驾驶者站在敌船甲板，随敌船运动
画面重点：两种船形、两种灯光、人物遮挡与尾波差异
```

这张图不强行同时展示位于镜头身后的第二桥。空间事实可以存在而不出现在每张图里。

`v_land` 则读取上岸时刻，camera.anchor_element_id 为 null。此时驳船成为玩家外部的被观察物件，不再被错误地当成固定贴在屏幕下缘的前景。

## 本轮拟交付

- 四张场景图：登船处、草岸显露、敌船接近、第二桥穿越。
- 一张船体近看图：从码头观察船首、侧舷、水线和甲板。
- 一张七格分镜板：覆盖整段经历。

共六个拟交付图像、八个可复用 View，分镜七帧。没有设置局部备选，本轮先观察同一主方案在移动过程中的一致性。图片数量不属于固定 Schema 要求。

先形成码头与驳船基准，再开展船体研究和其他场景图，最后组织分镜。引用依赖都只是计划，实际参考文件须在生成后取得。

## 与唱片店的对照结论

| 检视项 | 结果 |
| --- | --- |
| 是否把唱片店写死 | 没有；本例的区域、物件、材料和顺序全部不同 |
| 是否需要换一套顶层 Schema | 不需要；仍为项目约定、场景主方案、视觉探索 |
| 是否直接用 v0.1 就充分 | 不充分；需要 v0.2 的路线、移动、进度与镜头参照 |
| 静态实例是否被迫复杂化 | 不需要；新字段按需使用，旧实例维持固定位置和原有状态解释 |
| 是否已经能保证游戏好玩 | 不能；当前只保证设计关系可表达，仍需图像与运行样片检视 |
| 下一场景是否被捏造 | 没有；handoff 定义靠岸后的连续条件，next_scene_ref 为空 |

这次仍未覆盖多路线选择、任意折返、复杂战斗系统、实时载具物理和大型世界流式加载。也不应仅用两个实例就宣称 Schema 适用于所有游戏场景。
