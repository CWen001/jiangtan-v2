# 雨夜唱片店：三份契约的完整填写实例

日期：2026-09-10。用途：以具体设计检查 [字段草案](../fields-v0.1.md) 的表达能力。

这是填写实例，不是写死的场景模板。另见 [湿地驳船实例](wetland-barge/README.md)，它复用同一项目美术约定，用不同空间与移动经历检视 [v0.2](../fields-v0.2.md) 的通用字段。

这里的布局、造型、美术规则取值与图像数量都是提案，不代表用户已经选用，也不代表现有 Godot 小样已修改。三个 JSON 是可读的 Structured Output 样例；本轮没有生成这些计划中的图片。

## 阅读与调用顺序

| 顺序 | 文件 | 这份实例解决的设计问题 |
| --- | --- | --- |
| 1 | [project-art-direction.json](project-art-direction.json) | 怎样在建筑、人物、陈设之间保持漫画线条、明暗与细节尺度的一致 |
| 2 | [scene-design.json](scene-design.json) | 暗巷、小院与暖店如何成为一个有记忆点的空间，橱窗和人物怎样经得起近看 |
| 3 | [visual-production-plan.json](visual-production-plan.json) | 怎样用外景、内景、物件研究与连续分镜观察主方案，并比较一个局部橱窗备选 |

引用关系：`nightjar_first_visual_study@draft-01` → `nightjar_courtyard@draft-01` → `noir_comic@draft-01`。这些是草案内容版本，不是批准状态。

一次输入可用普通文字表达，不必再引入新的创作要求 Schema：

- 建立项目美术约定：“根据现有参考，提出三维空间与二维人物统一的手绘漫画表现语言，强调清楚体块和选择性细节。”
- 建立场景主方案：“沿用项目约定，设计暗巷转入小院、再进入暖亮唱片店的场景，重点是美术吸引力和沉浸感。”
- 建立视觉探索计划：“先看室内外整体效果，再研究橱窗厚度和人物融合；保留布局，提出一个橱窗局部造型备选。”

## 空间如何连接

下图只表示相对布局，没有施工尺度。方位在所有视角中固定。

```text
                         北
          ┌─────────────────────────┐
          │ 接头人   柜台            │
          │ 西侧通道       唱片架    │
          │         店内             │
          ├──门──────────弧形橱窗────┤
          │ 雨棚       （向院内凸出）│
          │          小院     低陈设 │
          │                          │
     ┌────┘                          │
     │ 转角                          │
     │ 狭巷                          │
     │                               │
     南端接港口街道（本包未设计）
```

室内、室外是 Zone 的属性。绕角和穿门由 Connection 连接。店面和橱窗跨接院落与室内，因此 `zone_ids` 有两个值，但每件物体仍只设计一次。

本实例没有楼上游玩区域，也没有新增攀爬路线。上层圆窗只服务于场景轮廓和光色。体验先用步行、绕角、推门、靠近和回望展开。

## 美术信息如何逐层变具体

以橱窗为例：

1. 项目美术约定规定大块明暗、选择性墨线、玻璃的透见与反光主次。
2. 场景的 `art.materials` 定义本场景旧木和玻璃的具体表现。
3. `elements.record_window` 指定弧形体块、三个玻璃分格、材料分布、窗框厚度与陈列层次。
4. `v_window_close` 指定从院内东南侧向西北看，清楚展示正面和侧面厚度。
5. `img_window_base` 使用主方案；`img_window_variant` 在同一个 View 下只改变指定木框轮廓。

这里没有把“好看”转成一个评分字段。设计信息本身要求 AI 作出具体决定：形体是什么、细节在哪里、光怎样照、从何处能看到。

## 本轮拟交付的图像

- 场景图三张：小院首次显露、转角之前、店内第一眼。
- 近看图三张：橱窗主方案、同视角橱窗备选、人物在环境中的融合研究。
- 体验分镜板一张、五格：靠近 → 绕角 → 推门 → 跨入 → 回望。

共七个拟交付图像，其中分镜板包含五个画格。这不是固定配额，也不等于七次工具调用；具体调用与重试取决于工具能力和图像效果。

`views` 共七个观察位置。分镜中的前三个场景视角复用已有 View，门槛与回望另有 View；不重复写一套可能漂移的构图。共用 View 是共用设计意图，图像连续性仍需要实际参考图支持。

## 出图依赖与可见内容

推荐先取得能代表主方案的小院图 `img_court`，再开展入口、室内和橱窗主方案；人物近看引用室内图，橱窗备选引用橱窗主方案；分镜板引用已得到的入口、小院与室内图。

计划中的依赖 ID 不是图片路径。执行时拿到真实文件后再传入工具；本轮没有声称这些图片已经存在。

给 `img_window_variant` 组织输入时，需要取得：

- 项目美术约定中相关的线条、明暗、玻璃和融合要求。
- 主场景中的方位、店面关系、光色、旧木和玻璃材料定义。
- `record_window` 的基准造型与材料分布。
- `v_window_close` 的观察位置、构图与状态。
- `window_tapered_frame` 对原有木框的差异说明。
- `img_window_base` 的实际图像，以及本图的版式要求。

共同风格和空间事实应保留，但不必把完全不相关的柜台描述逐字塞进每个橱窗出图指令。

## 两类变化的走读

### 推门：画面状态发生变化

主方案 `initial_state` 写门关闭。门槛 View 写门打开一半，室内与回望 View 写门完全打开。每个 View 的状态都相对于主方案解释，单独生成也不会因缺少上一帧而失去门的状态。

这个过程不产生新的 SceneDesign：门的位置、形状和开启方式没变。

### 选用新的橱窗：场景设计发生变化

假设以后确实生成图片并选用 `window_tapered_frame`，才将新轮廓写入 `SceneDesign.elements.record_window.form` 并修订主方案版本。下一轮计划引用新版 SceneDesign。

随后重新检视能看见橱窗的院落视角、橱窗近看、回望及相关分镜。若人物近看图里没有这处橱窗，不需要因橱窗更新而无差别重做。旧图仍对应旧版本，不改写其来源。

本段只是演示交接，不表示这个备选已生成或被选中。

## 本次设计走读的结论与限制

| 问题 | 实例中的表达 |
| --- | --- |
| 室内外看见同一橱窗 | 跨接两个区域的一个 Element，多处 View 引用 |
| 大量贴图怎样保持美术秩序 | 全局材料定义＋局部分布和处理；普通墙面保留安静区域 |
| 主要物件是否只有名称 | 分别给出轮廓、比例、构成、表现分工与融合要求 |
| 转角是否一定另建场景 | 用 Connection 表达隐藏与显露，仍属于同一个主方案 |
| 静帧如何支持体验分镜 | Frame 引用 View，增加动作与画面变化 |
| 局部备选会不会污染主方案 | Variant 单独描述差异，只有指定交付使用；选用后回写 |
| 实际结果是否提前编造 | 只有交付 ID 和依赖，无虚构图片路径或完成状态 |

这些说明字段能够表达一条具体设计链，尚不能证明画面已经有冲击力。相对尺寸与示意布局也不证明真实视锥、遮挡和通行成立，后续仍需图像探索及可行走样片。

下一轮适合优先审看：艺术字段是否足够具体而不过度碎片化、共用 View 的写法是否顺手、该实例的场景美术主张是否值得拿去出图。三份 JSON 的可解析性仅是文件完整性检查。
